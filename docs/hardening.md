# Version 2 project administration and demo

Project navigation includes Components, Environments, and Settings. A Contributor or Owner can create environments and components, and declare dependencies between components in the same project. The Components form only creates `Declared` edges; externally supplied `Observed` records remain the caller's responsibility. Viewers can inspect the pages without edit controls. Owners can update name, description, slug, and visibility, add an already signed-in local user by email as Contributor or Viewer, and archive a project without deleting its history.

Commerce Demo keeps its fixed project, environment, and component IDs. Development seeding also adds a deterministic story, two tasks, an active payment bug, tags, and a link from that bug to Payment Service. A local seed actor records the example activity but receives no project membership or ownership. Repeated startup does not duplicate work and does not restore a link that a user removed.

For the demo, sign in and open Commerce Demo. Create or inspect the payment bug on Boards, assign it, and move it to Active. Link it to Payment Service in the detail drawer. Open Topology and select Payment Service; its active work appears beside runtime state, deployments, and events. Simulate degradation in Development mode, observe the live node and event, run potential impact analysis, recover, and close the bug. The project overview shows a board snapshot and merged recent activity. The environment comparison page distinguishes missing records from proven component absence.

The board uses explicit state controls that work from a keyboard. The work-item drawer starts focus on its close button and closes on Escape. Topology has a labeled component selector as a keyboard alternative to choosing a graph node. Statuses use text as well as color. Tablet layouts stack graph detail and project panels; the board reduces from four columns to two and then one.

The full Compose smoke run verified Keycloak discovery, readiness 200, anonymous API 401, a signed-in project overview, five Commerce Demo work items after migration, a checked Payment Service link in the board drawer, active linked work in topology detail, and the environment comparison table. In a separate test project, the browser created a service and database, declared a dependency, then reloaded a topology showing both nodes and the edge. The EF history in Compose includes all seven migrations.

The final rebuilt stack also passed a live check on that test project: degrading the database updated its graph node and created a visible event without reloading the page; impact analysis named the service as a direct dependent; recovery returned the database to Healthy. The final backend build and 17 tests, frontend lint and production build, and EF pending-model check passed.
